# Политика безопасности OrderFlow Platform

Версия: 1.0 · Владелец: owner@orderflow.example.com · Ответ: 90 дней на подтверждение,
30 дней на патч для критических находок.

Документ описывает модель угроз, применяемые контроли и порядок раскрытия уязвимостей
для этого репозитория. Связанные репозитории экосистемы (core, jobs, scale, services)
ведут собственные SECURITY.md.

---

## 1. Границы анализа

**В зоне анализа:** код API, конфигурация CI/CD, Docker-образ и образы зависимостей,
конфигурация nginx/Prometheus/Grafana, скрипты деплоя, секреты и их хранение.

**Вне зона анализа:** физическая инфраструктура провайдера, клиентские устройства
пользователей, внутренняя сеть хостера, сам код зависимостей (покрывается аудитом).

**Конфиденциальность:** публичный репозиторий. Всё, что лежит в git, считается
публичным — туда не должны попадать токены, ключи и пароли даже в перечёркнутом виде.

## 2. Модель угроз (STRIDE)

| # | Категория | Угроза для OrderFlow Platform | Контроли в проекте | Статус |
|---|-----------|-------------------------------|--------------------|--------|
| 1 | **Spoofing** — подмена клиента или сервиса | Подделка Origin для кросс-доменного вызова; запрос «от имени» другого сервиса без идентификации | Ограничение `CORS_ORIGINS` явным списком; TLS на edge через nginx + certbot; интерфейсы БД и Grafana/Sentry слушают только `127.0.0.1`; аутентификация API — в roadmap (см. §5) | Частично закрыто |
| 2 | **Tampering** — подмена артефакта | Изменённый образ между сборкой и продом; правка конфигов на сервере вне git | Образ тегируется по `github.sha` и `v*`; деплой забирает конфиги только через `rsync` из git; `docker compose pull` с фиксированными версиями образов (postgres 16, nginx 1.27, prometheus 2.55.1, grafana 11.3.1); `read_only` корневых ФС контейнеров | Частично закрыто |
| 3 | **Repudiation** — отсутствие следов действий | Невозможно восстановить, кто и что менял и когда падало | Структурированные JSON-логи с `request_id`, `service`, `environment`; access-лог nginx; Sentry с трассировкой; история гит и релизы `gh release create --generate-notes` | Закрыто |
| 4 | **Information Disclosure** — утечка данных | Секрет в репозитории или в логе; раскрытие стектрейса клиенту | `gitleaks` (конфиг `security/.gitleaks.toml`) в стадии 4 CI — на каждый PR и push; `pip-audit --strict` для зависимостей; `.env` в `.gitignore`, в репо только `.env.example` с плейсхолдерами; в production тело ошибки отдаётся через обработчик `app/core/exceptions.py`, детали — только в логах и Sentry; `GITLEAKS_CONFIG` и `--redact` в CI | Закрыто |
| 5 | **Denial of Service** — отказ в обслуживании | Утечка соединений с БД; зависший процесс; исчерпание места; перебор запросов | Healthcheck у всех долгоживущих сервисов; `restart: unless-stopped`; таймауты в nginx (`proxy_read_timeout 30s`) и в `get_session`; `depends_on: service_healthy` — БД поднимается до API; `deploy.sh` сам откатывается при неуспешном health-чеке; на edge — `limit_req` 10 r/s (burst 20) для `/api/*` | Частично закрыто |
| 6 | **Elevation of Privilege** — повышение привилегий | Контейнер от root; запись в ФС контейнера; примонтированный сокет Docker | Нестандартный пользователь (`uid 10001`) в `infra/Dockerfile`; `read_only: true` + `tmpfs` для `/tmp`; `no-new-privileges:true` у всех сервисов; сеть `backend` помечена `internal: true`, API не торчит в интернет напрямую, только через nginx | Закрыто |
| 7 | **Supply chain** — компрометация цепочки поставок | Уязвимая зависимость; подменённый базовый образ | `pip-audit --strict` в CI; Dependabot для `pip` и `github-actions`; пиннинг тегов базовых образов; официальные образы `postgres`, `nginx`, `prometheus`, `grafana`; минимальный слой зависимостей в multi-stage сборке | Закрыто |

## 3. Контроли в CI/CD (гейты, которые нельзя обойти)

| Стадия | Инструмент | Условие падения |
|--------|-----------|-----------------|
| 1 · lint | `ruff check` + `ruff format --check` | Любое нарушение стиля |
| 2 · typecheck | `mypy --strict` (задан в `pyproject.toml`) | Любая ошибка типов |
| 3 · test | `pytest --cov=app --cov-fail-under=75` | Покрытие ниже 75% |
| 4 · security | `bandit -c pyproject.toml -r app`, `pip-audit --strict`, `gitleaks` | Любая находка high/любой известный CVE/любой секрет |
| 5 · build | `docker build` + smoke `/health`, `/ready`, `/metrics` | Образ не собрался или не отвечает |
| 6 · deploy | `deploy/deploy.sh` | Health-чек на проде не прошёл → автоматический откат |

Ветки защиты: изменения идут только через PR в `main`; секреты хранятся в GitHub
Actions secrets (`SSH_HOST`, `SSH_KEY`) и vars (`DEPLOY_USER`), в логи не попадают.
Правила репозитория (branch protection, required reviews, CODEOWNERS) настраиваются
вручную в настройках репозитория и не версионируются этим проектом.

### Локальная проверка перед PR

```bash
python -m ruff check . && python -m ruff format --check .
python -m mypy app
python -m pytest --cov=app --cov-fail-under=75
python -m bandit -c pyproject.toml -r app -q
python -m pip-audit --strict
gitleaks dir . --config security/.gitleaks.toml --redact --exit-code 1
python scripts/check_configs.py
```

## 4. Раскрытие уязвимостей

1. **Не публикуйте** детали в issue, в публичном чате и в твитах до выпуска патча.
2. Пришлите описание на `security@orderflow.example.com` (или через приватный
   GitHub Security Advisory: *Security* → *Report a vulnerability*).
3. В отчёте укажите: версия/коммит, шаги воспроизведения, влияние, предложенный патч.
4. Мы подтверждаем получение за 90 дней, оцениваем CVSS и согласуем дату раскрытия.
5. После патча — кредит в `CHANGELOG` (по желанию исследователя).

**Что считается находкой:** обход аутентификации, RCE, инъекция SQL/SSRF, утечка
секретов, отказ в обслуживании с подтверждённым воспроизведением, компрометация
цепочки сборки.

**Что не считается:** находки в зависимостях без рабочего эксплойта (идут в backlog
Dependabot), сканирование без данных, социальная инженерия, DoS без воспроизведения.

## 5. Известные ограничения (честный список)

- API сейчас **без аутентификации и авторизации** — это осознанный scope
  портфолио-проекта; в roadmap `GET/POST /api/v1/flags` закрываются OIDC + RBAC.
- **Rate limiting** есть только на edge (`limit_req`, 10 r/s, burst 20 в nginx);
  у самого API нет собственного лимитера и защиты от перебора по сессиям — это в
  roadmap.
- Бэкапы БД описаны в `docs/RUNBOOK.md`, но **автоматизация бэкапов не включена** в
  репозиторий — считается операционной задачей хостера.
- `ansible-playbook --syntax-check` на Windows недоступен: плейбук проверяется
  YAML-парсером (`scripts/check_configs.py`), полноценный прогон — только на Linux.
- Конфиги nginx и Grafana alerting проверяются парсером и ревью, не `nginx -t`.
